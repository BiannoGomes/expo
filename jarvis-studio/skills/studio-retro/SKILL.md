# studio-retro

The studio compounds only if every project leaves something behind. Take 5 minutes, not an essay.

## 1. Write the entry

Append to `STUDIO/learnings/motion-learnings.md` using the entry template in that file:
project, brand, date, the ship target, and whether it actually shipped.

- **Worked**: specific and reusable ("gold rule drawn at the focal point read as separation; 350 ms `power3.inOut`").
- **Failed → fix**: from `review/log.md`, the hypotheses that were right, and the ones reverted.
- **Values that earned their place**: durations, eases, sizes, positions.
- **Bianno's notes**: verbatim, and the variable that fixed each one (this is how the studio learns his taste).
- **PROPOSED values confirmed or overridden**: then update the brand's `MOTION.md`.
- **Tool issues**: anything a script or skill got wrong. Fix the tool, or log it for the next session.
- **Audience result**: only numbers Bianno supplies (views, saves, comments, clicks). Never estimate them. Write "pending" if unknown.

## 2. Promote

- **A mistake seen twice** becomes a proposed rule. Propose adding it to the brand's `MOTION.md`
  "Never" list, or to the house rules. Bianno approves brand rules.
- **A technique used twice** becomes a library component. Extract it to
  `STUDIO/library/<brand-or-shared>/<name>.md` (the snippet, where it came from, when to use it).
- **A strong result** (by Bianno's numbers) becomes the new default for that format. Note it in `motion-learnings.md` under "Defaults".

## 3. Close the loop on shipping

If the piece hasn't been posted or sent, the retro's last line is the **one** next action to
get it in front of a human, with a date. The studio exists to ship. A finished, unshipped
render goes in the queue, not the archive.
