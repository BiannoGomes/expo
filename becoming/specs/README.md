# BECOMING — MVP Specifications

These specs close the five highest-priority gaps identified in
`../gap-analysis.md`. Read them in order; each builds on the previous.

| Spec | Closes gap | Contents |
| --- | --- | --- |
| [01 — Domain Taxonomy](01-domain-taxonomy.md) | Dropped 12-Domain / 1% Blueprint | The dimension system every engine reasons over |
| [02 — Personal Model & Memory](02-personal-model.md) | Unspecified memory + schema, no provenance/confidence | Schema, write path, retrieval, correction loop |
| [03 — Daily Loop](03-daily-loop.md) | Unspecified daily surfaces, no re-entry design | Morning screen, evening debrief, missed-day behavior |
| [04 — Safety & Privacy Mechanisms](04-safety-privacy.md) | Principles without mechanisms | Crisis flow, consent model, data rights, third parties |
| [05 — Cost Model & Acceptance Criteria](05-cost-model-acceptance.md) | No unit economics, unfalsifiable MVP bar | Token budgets, model tiering, pass/fail criteria |

Status: **draft for review**. Nothing here is code; everything here is
buildable. The specs assume the MVP loop from Part 2 §52 and the concepts of
Part 1. Where a spec makes a decision the briefs left open, the decision is
marked **[DECISION]** so it can be overturned deliberately rather than by
accident.
